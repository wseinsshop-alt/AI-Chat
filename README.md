## 📦 Ровно четыре файла

```text
AI-Chat/
├── README.md          # Документация
├── main.py            # Весь исполняемый код
├── config.json        # Общие настройки без реальных секретов
└── requirements.txt   # Зависимости
```

Приложение создаёт рабочие файлы **вне репозитория**: SQLite, ключ шифрования, локальные настройки и резервные копии. В main.py — обычный читаемый Python без зашифрованных модулей и загрузчика чужих скриптов.

## 🚀 Быстрый старт

Нужен **Python 3.10 или новее**.

```bash
python -m venv .venv
```

Активируй окружение:

```bash
# Linux / macOS
source .venv/bin/activate
```

```powershell
# Windows PowerShell — можно вызывать Python без активации
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py --setup
.venv\Scripts\python.exe main.py
```

На Linux в активированном окружении:

```bash
python -m pip install -r requirements.txt
python main.py --setup
python main.py
```

Для русскоязычных PDF на Ubuntu/Debian:

```bash
sudo apt-get update
sudo apt-get install -y fonts-dejavu-core
```

При настройке введи токен от **@BotFather** и свой **числовой Telegram ID**. Токен вводится скрыто. Они сохраняются в локальном `settings.json` в рабочем каталоге данных, а не в публикуемом `config.json`.

### Первый разговор

1. Открой бота и отправь `/start`.
2. Задай личный пароль и повтори его.
3. Нажми **«➕ Панель»**, введи название, API base URL и API-ключ.
4. Выбери модель — появится отдельный чат.
5. Пиши вопросы, отправляй фото или загружай документы.

Если вставить `https://example.com/chat`, бот предполагает API `https://example.com/v1`. Если в документации панели указан другой base URL, используй **точный адрес из её раздела API**. Поддерживается HTTPS; локальные и служебные IP-адреса отклоняются.

## ⚙️ Конфигурация

`config.json` задаёт настройки приложения. Реальные секреты лучше хранить в локальной настройке `--setup` или переменных окружения:

| Переменная | Назначение |
|---|---|
| `AI_CHAT_TOKEN` | Токен Telegram-бота |
| `AI_CHAT_ADMIN_IDS` | Числовые ID администраторов через запятую |
| `AI_CHAT_DATA_DIR` | Абсолютный путь к рабочему каталогу данных |
| `AI_CHAT_CONFIG` | Другой путь к `config.json` |

По умолчанию данные находятся:

- Linux: `$XDG_DATA_HOME/ai-chat` или `~/.local/share/ai-chat`.
- Windows: `%LOCALAPPDATA%\AIChat`.

| Поле | По умолчанию | Значение |
|---|---:|---|
| `invite_only` | `true` | Регистрация по приглашениям; администраторы входят без приглашения |
| `session_hours` | `24` | Срок входа после проверки личного пароля |
| `backup_hours` | `24` | Интервал автоматических копий; проверка каждые 5 минут |
| `backup_keep` | `7` | Число сохраняемых локальных копий |
| `daily_tokens` | `100000` | Начальный локальный дневной лимит; пользователь меняет свой через меню |
| `daily_usd` | `0` | Локальный USD-лимит; `0` отключает его |
| `max_output_tokens` | `4096` | Максимальный размер ответа в запросе API |
| `history_messages` | `20` | Сколько последних сообщений передавать модели |
| `max_file_mb` | `10` | Лимит вложения; сверху ограничен 19 МБ |
| `workers` | `4` | Число одновременно выполняемых заданий |
| `prices` | `{}` | Тарифы моделей для локального расчёта стоимости |

### 💰 Расходы и ограничения

Бот использует `usage` провайдера. Если API не вернул его, запрос прерван или процесс упал, учитывается **консервативная оценка**, помеченная в статистике. Цена без известного тарифа остаётся **неизвестной**, а не нулевой.

Сутки считаются по **UTC**. Запрос резервирует лимит до обращения к API. Текст оценивается по UTF-8-байтам с запасом; для изображений используется дополнительный запас. Это не токенизатор конкретной модели.

Пример структуры тарифа, **условные числа — замени ценами своей панели**:

```json
{
  "prices": {
    "your-model-id": {"input": 1.0, "output": 3.0},
    "https://example.com/v1|another-model": {"input": 0.5, "output": 2.0}
  }
}
```

Тарифы — USD за миллион входных/выходных токенов. Ключ `base_url|model` имеет приоритет над общим именем модели.

При включённом USD-лимите операции с неизвестным тарифом блокируются до запроса. Голос тарифицируется отдельно через `transcription_usd_per_minute` и `speech_usd_per_million_characters`. Вызовы голоса отражаются в числе операций, но не имеют искусственно придуманных текстовых токенов.

**Локальный лимит не является банковской гарантией расходов:** провайдер может иначе учитывать изображения, reasoning, кэш, отменённую генерацию и дополнительные услуги. Для строгого денежного ограничения установи лимит также в самой панели. Эти настройки задаёт владелец своего ключа; они не предназначены для выставления счетов другим пользователям.

### 🎙 Голос

По умолчанию: распознавание `whisper-1`, озвучка `tts-1`, голос `alloy`. Имена настраиваются в `config.json`.

Панель должна поддерживать multipart-загрузку `/audio/transcriptions` и/или `/audio/speech`. Поддержка OGG зависит от провайдера. Если панель отвергает голосовое Telegram, отправь поддерживаемый аудиофайл или используй текст. MP3-озвучка помечается как сгенерированная ИИ. Распознавание и последующий ответ — **два отдельных вызова API**.

### 📄 Документы и изображения

- PDF: текстовый слой, до 60 страниц. Скан без текста отправь фотографией — OCR в приложении отсутствует.
- DOCX: абзацы и таблицы. XLSX: значения первых пяти листов, до 1000 строк × 30 столбцов на лист.
- Для анализа передаются первые 60 000 символов; при сокращении бот сообщает об этом.
- Изображение уменьшается до 1600 × 1600 и отправляется как base64, **без Telegram URL с токеном бота**.
- Формирование файлов происходит локально. Модель пишет содержимое, приложение создаёт настоящий файл.
- Для Excel модель должна вернуть JSON-массив строк. Если она вернула обычный текст, выбери «Создать документ → XLSX» и уточни запрос.
- Сохранение PDF/DOCX не повторяет весь рендеринг Markdown: сложные таблицы, формулы и графики лучше запросить отдельным подходящим форматом.
- Ячейки CSV/XLSX, похожие на формулы, экранируются, чтобы не исполнять формулы из модельного текста.

## 🔐 Доступ и резервные копии

Панели, избранное, чаты и история привязаны к Telegram ID. Пароль хранится как PBKDF2-хеш с солью; после пяти неверных попыток действует пауза на пять минут. Смена пароля требует старого. Встроенного восстановления забытого пароля нет.

API-ключи зашифрованы Fernet-ключом `secret.key`. Переписка хранится в SQLite как текст. Пароль ограничивает вход через бота, но не защищает от администратора сервера, имеющего базу и ключ. Бот старается удалять сообщения с паролями и API-ключами; эти сообщения всё равно проходят через Telegram.

Администратор может создать **одноразовую ссылку на 24 часа**. По умолчанию посторонние не могут зарегистрироваться. Ссылка допускает одного нового пользователя; уже зарегистрированные пользователи не расходуют приглашение.

**Копируй `secret.key` отдельно от зашифрованных резервных копий.** Без него нельзя открыть сохранённые API-ключи и импортировать копию.

В админке доступны экспорт и импорт. Импорт требует пароль, файл и подтверждение полной замены. Файл расшифровывается и проверяется на отдельной базе; загруженный SQL не исполняется. Перед заменой создаётся локальная копия, после импорта все сессии сбрасываются. При активных заданиях импорт блокируется.

Автоматические копии лежат в `backups/` рабочего каталога данных. Копии на том же диске не спасают при потере сервера — переноси их на отдельное хранилище.

## 🖥 Круглосуточная работа

На Ubuntu/Debian положи четыре файла в `/opt/ai-chat`, создай `.venv` и выполни начальную настройку:

```bash
cd /opt/ai-chat
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
AI_CHAT_DATA_DIR=/var/lib/ai-chat .venv/bin/python main.py --setup
```

Пример systemd unit — сохраняется **на сервере**, не добавляется в репозиторий:

```ini
[Unit]
Description=AI Chat Telegram Bot
Wants=network-online.target
After=network-online.target

[Service]
WorkingDirectory=/opt/ai-chat
Environment=AI_CHAT_DATA_DIR=/var/lib/ai-chat
Environment=PYTHONDONTWRITEBYTECODE=1
ExecStart=/opt/ai-chat/.venv/bin/python -u /opt/ai-chat/main.py
Restart=always
RestartSec=5
UMask=0077
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ai-chat
sudo systemctl status ai-chat --no-pager
```

Порты открывать не нужно: используется long polling. Запускай **один процесс на один Telegram-токен и каталог данных**. Останови старую службу, если она использует тот же токен.

### Переход с прежнего tg-ai-cabinet

1. Останови прежнего бота и сохрани копию его каталога данных.
2. Перенеси **оба** файла `bot.db` и `secret.key` в выбранный `AI_CHAT_DATA_DIR`.
3. Выполни `main.py --setup` с прежним токеном и ID администратора.
4. Запусти AI Chat. Старая таблица истории автоматически преобразуется в отдельные чаты; панели и пароли сохранятся.

Формат новых `.enc`-копий — версия 2. Для переноса старой версии используй файлы базы и ключа при остановленных процессах, а не старый `.enc`.

## ❓ FAQ

**Панель работает в браузере, но не подключается.**
Нужен именно API base URL и API-ключ. Cookie браузера и пароль от сайта не подходят. Кнопка проверки тестирует `/models`; это не доказывает поддержку голосовых или изображений.

**Модель не отвечает в потоковом режиме.**
В настройках панели переключи режим ответа. API должен поддерживать `/chat/completions`; поток использует SSE и `stream_options.include_usage`. Приложение не повторяет платный запрос автоматически при ошибке.

**«Стоп» нажат, но выполнение ещё продолжается.**
Остановка кооперативная: проверяется при чтении ответа. Если сервер не присылает данные, сетевое чтение может занять до 60 секунд. Отмена не гарантирует отмену списания у провайдера.

**Откуда берётся история?**
В базе сохраняется до 100 последних сообщений чата, в модель отправляется настраиваемый хвост с дополнительным ограничением размера. История не синхронизируется с сайтом ChatGPT. Кнопка скачивания под ответом сохраняет последний ответ указанного чата.

**Почему четыре файла, но после запуска есть данные?**
Четыре файла — состав исходников. Рабочие данные и секреты нужны для работы и создаются в отдельном каталоге вне проекта. Не публикуй этот каталог.
